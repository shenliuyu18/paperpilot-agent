# PaperPilot v6.1 设计规格：作者元数据与审稿意见映射

- 日期：2026-10-22
- 版本：6.1.0
- 状态：已实施
- 前置版本：v6.0.0

## 1. 背景

v6.0 的投稿包只用了标题、作者名、单位、邮箱、基金。实际投稿还需要通讯作者、ORCID、作者贡献、
数据/代码可用性、利益冲突与致谢；双盲导出若只删作者而保留致谢，仍可能泄漏身份。审稿意见也只能靠人
翻草稿定位。

## 2. 范围

1. 作者字段：`orcid`、`corresponding`；稿件字段：`contributions`、`data_availability`、
   `code_availability`、`competing_interests`、`acknowledgments`。
2. ORCID：ISO 7064 11,2 校验；最多一位通讯作者。
3. 盲审：DOCX/PDF 去除作者/单位/基金/**致谢**；数据/代码可用性与利益冲突保留；标题页单独保留作者。
4. 正文元数据：DOCX/PDF 在正文后渲染致谢、数据/代码可用性、利益冲突。
5. 审稿映射：每条意见按词法重合定位最多 3 个草稿块；回复模板带建议定位。
6. UI：稿件抽屉新增字段；投稿抽屉新增意见文本框、映射表、带意见的回复模板。

## 3. 规则

- ORCID 正则 `^[0-9]{4}-[0-9]{4}-[0-9]{4}-[0-9]{3}[0-9X]$`，再用 ISO 7064 校验位；错误直接 422。
- 通讯作者最多一位；多于一位 422。
- 预检：有作者但没有通讯作者 → 提醒；已存 ORCID 校验位错误 → 提醒。
- 投稿检查：无 ORCID / 无利益冲突 / 无数据可用性 → 提示（info）；双盲档案提示致谢会移除。
- 审稿映射：`grounding.overlap(comment, block.text)` 排序；最多 20 条意见、单条 ≤2000 字；
  只读，不写草稿、不生成最终回复。
- 回复模板：带意见时表格包含意见原文、建议章节/段落与待填写列。

## 4. API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/projects/{id}/reviewer/map-comments` | `{comments:[...]}`，返回 items/matches/suggestion |
| POST | `/api/projects/{id}/reviewer/response-template` | `{comments:[...]}`，返回带定位的 Markdown |

`/api/meta` 特性位 45 → **47**：`author_metadata`、`reviewer_mapping`。

## 6. 非目标

- 不向 ORCID 公共 API 验证归属；不做 CRediT 角色枚举校验。
- 不把审稿映射当作对意见的理解；不自动生成最终回复。
- 不改变 v6.0 的档案边界（参考要求，不是官方模板）。
