# PaperPilot · 评测方案

## 1. 评测目标

PaperPilot 的评测回答三个问题：

1. **链路是否可靠**：检索、解析、抽取、对比、转化是否按预期工作？
2. **证据是否站得住**：每个结论能否回到原文？有没有无证据断言？
3. **是否真的省时间**：完成一次 5 篇论文的初步综述，比手工 + 通用聊天模型快多少？

## 2. 评测集

当前内置 41 条回归用例（`data/eval_set.json`），覆盖 14 个维度：

## 4. 人工评测设计

### 4.1 语料

- 3 个主题：存算一体 ADC、RISC-V 乱序执行、低功耗 SRAM；
- 每个主题 8–10 篇论文，共 20–30 篇；
- 其中 5–10 篇有开源代码，5 篇包含相互矛盾的结论；
- 每篇人工标注 10–12 个字段：问题、方法、创新点、数据集、指标、baseline、测试条件、局限、代码链接。

### 4.2 流程

1. 两位评审独立标注；
2. 计算字段级一致性（Cohen's kappa）；
3. PaperPilot 抽取结果与 gold label 对比；
4. 第三位评审仲裁分歧；
5. 记录失败案例类型：漏抽、错抽、条件误配、证据错位、过度推断。

### 4.3 用户研究

- 8–10 位本科生/研究生；
- 任务：用 5 篇论文完成一页综述 + 一张对比表；
- 对照组：谷歌学术 + 通用聊天模型 + Excel；
- 实验组：PaperPilot；
- 记录完成时间、正确字段数、主观可信度、SUS。

| 规则模式 vs LLM 模式 | 观察抽取覆盖率、问答综合质量与成本 |

## 6. 当前局限

- 回归集只有 41 条，规模小（另有 461 条测试、工作区端到端评测、13 项 Copilot 专项与内容质量评测）；
- 工作区评测跑在离线演示语料上，指标说明链路正确性，不代表真实文献上的抽取质量；
- 草稿词法核查以词重合与数值一致性为准；v3.0 虽新增语义支持核查，但离线仍是规则初判、在线仍需真实模型抽检，且没有人工标注集可对照；
- 离线模式的结构化字段为人工校订，不代表任意论文的自动抽取质量；
- 尚未做多评审一致性；
- 用户研究尚未开始，耗时为设计目标，不是实测值；
- 无密钥公共翻译受第三方额度影响，模型翻译质量取决于所配置模型；OpenCitations 引用网络只覆盖 DOI 记录，外部来源存在速率与覆盖差异。

### 内容质量评测（v5.0）

`scripts/eval_content.py` 在金标集上计算六项指标，`--strict` 未达标即非零退出：

| 指标 | 阈值 | 含义 |
|---|---|---|
| 支持精度 | ≥ 0.90 | 判为 supported 的主张中，标签确为 supported 的比例 |
| 支持召回 | ≥ 0.75 | 标签为 supported 的主张中，被判为 supported 的比例 |
| 过度严格率 | ≤ 0.05 | 标签为 supported 却被判 unsupported 的比例 |
| 数值一致率 | ≥ 0.95 | 数字缺失类探针中，未被误判为 supported 的比例 |
| 证据覆盖率 | ≥ 0.80 | 绑定至少一条证据的正文块占比（需 `--project`） |
| 矛盾召回 / 误报 | ≥ 0.80 / ≤ 0.15 | 构造矛盾对上的检出率与误报率 |

`--online` 时经统一网关调用模型复核：模型只能给出 `stance / reason / counter_quote`，
`counter_quote` 必须是证据原文子串，否则丢弃；**规则与模型不一致时以规则为准**，并统计一致/分歧/降级，
用于校准模型而不改变门禁。

当前评测集由三部分组成：`build_golden_seed.py` 的 32 条构造探针、`build_golden_hard.py` 的 37 条
同领域硬负例、`build_golden_multitopic.py` 的 351 条多主题构造探针（4 主题 × 6 篇真实摘要），
合计 **420 条**。它们的分数只说明"判定器与构造方式一致"；人工标注的 4 主题 × 6 篇 / ≥200 条
仍未完成签字，在那之前不应对外引用为"人工金标集达标"。

### 4 主题语料与多主题构造集（v5.2）

```bash
python scripts/fetch_golden_corpus.py                 # Crossref + Europe PMC，4×6 真实摘要
python scripts/golden_workbench.py build --corpus-dir data/eval/golden/corpus   # 225 条候选，label 为空
python scripts/build_golden_multitopic.py             # 351 条构造探针（4 个主题文件）
```

- 语料与候选文件随仓库提交，离线可复现；候选 `label` 必须由人填写，`eval_content` 会跳过未标注集合。
- 多主题构造集对每篇论文构造四类探针：逐字 supported、追加从句 partial、改数字 partial（`probe=missing_number`）、
  同主题另一篇 unsupported。构造时避开“新数字也在原句”“重复同一从句不增加唯一 token”两类假探针，
  并跳过分词器不支持的非 ASCII/CJK 句子。
- 当前实测：420 条，支持精度/召回/过度严格率/数值一致率/准确率均为 1.000；这是构造集回归结果，
  **不是人工质量结论**。

### 同领域硬负例（v5.1）

v5.0 的构造探针里，跨论文句子大多与证据词汇相距很远，掩盖了"同领域、不同论文"的误判。
v5.1 补了结构性硬负例：两篇论文的句子重合度落在 0.20–0.45，但主张的数值与系统名称大多不在证据里。
`classify_claim` 在重合度未达支持阈值时检查 `number_overlap < 0.5` 或 `marker_overlap < 0.25`，
命中即判 `unsupported`。演示语料中该区间的 32 条跨论文句子由 31 条 `partial` 降为 0 条。

### 金标集工作台（v5.1）

```bash
python scripts/golden_workbench.py build          # 候选池，label 留空
python scripts/golden_workbench.py stats          # 各主题论文/候选/已标注/缺口
```

- 候选文件放在 `data/eval/golden/candidates/`，`provenance: human-required`；
  `eval_content` 只读顶层已标注集合，未标注或 `needs-adjudication` 的集合会被跳过。
- `merge` 对分歧条目不选边：保留双标签、清空 `label`、写入 `disagreements`，由第三人裁决。
- 目标与标注规范见 `docs/金标集标注指南.md`。

### 投稿与审稿自查（v6.0）

- 投稿检查与审稿视角是**规则自查**，不进入内容质量指标；它们复用 `preflight`、`draft_audit`、主张三档与矛盾记录。
- 可复现命令：`python scripts/acceptance.py` 的 16.1–16.6；`tests/test_submission.py` 覆盖档案、检查、亮点、盲审、投稿包、审稿报告与 RIS/EndNote 往返。
- 投稿包不含人工金标集结论；审稿推荐等级只反映规则问题数量，不能当作同行评审结果或期刊决定。


### 作者元数据与审稿映射（v6.1）

- `tests/test_submission.py` 覆盖 ORCID 校验位、单一通讯作者、盲审去致谢、标题页/投稿信富元数据、
  审稿意见映射排序与两条 API。
- 映射是词法重合排序，只用于定位段落；不进入内容质量指标，不代表对审稿意见的理解或同意。
