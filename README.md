## 它解决什么问题

本科生进组、研究生开题、课程论文调研，常见流程是：搜索论文 → 读摘要 → 手工做对比 → 最后仍然不知道创新点在哪、怎么复现，读过的笔记也散落在各处。

PaperPilot 把这条链路做成一个可运行的 Agent：

- **项目 Copilot**：在项目内直接提问“下一步做什么、有哪些证据、草稿哪里有问题、两轮差异在哪”；答案只基于项目资产，附证据/草稿/运行引用，无依据时明确说不足；建议动作需二次确认，后端不自动执行
- **研究项目工作区**：一个项目承载研究问题、范围、约束与阶段，下挂多轮运行；运行结束把已核对证据、开放问题、决策与论文快照提升到项目记忆，新一轮按记忆播种并记录 `seed_summary`；支持归档、恢复、删除与 v1.0 独立任务归集
- **实时干预与进度流**：7 种运行中控制指令在动作边界生效（暂停/恢复/重新规划/切换自主程度/补充约束/改选论文/注入问题），SSE 快照流推送进度，代理不支持时自动降级轮询；同项目 2–3 轮运行可对比动作、证据与共有/独有证据
- **结构化草稿工作台**：章节 + 段落块、段落级证据锚点与引用键、`revision` 乐观锁与 409 冲突处理、版本快照与恢复、8 条核查规则分级定位，另加语义支持核查（支持/部分/不支持/无证据，只读），导出 Markdown/LaTeX/BibTeX/JSON
- **稿件与导出**：稿件元数据、GB/T 7714-2015 / APA 7 / IEEE 三种学术样式（另保留 numeric / author-year），文内标记与参考文献表由同一引擎生成并做一致性校验；课程论文级 DOCX（页眉、页脚页码、题注、参考文献表）与投稿前检查清单
- **持续研究**：检索订阅（手动立即执行，自动调度默认关闭）、论文指纹增量索引（DOI → arXiv → 标题哈希）、新论文差异定位与冲突写入矛盾记录
- **自适应研究任务**：输入研究目标后，Planner 按“证据是否足够”动态安排检索、精读、追问、对比、选题、写作、撰写章节、核查与收束；检索/选题检查点可改选论文、选择方向，支持暂停、恢复、停止收束与 Markdown 简报下载
- **证据账本与开放问题**：精读与追问的证据统一入账（论文/章节/页码/quote/核对状态）；未解决缺口转成开放问题，驱动额外追问或检索；人工决策与预算全程可审计
- **查找**：检索计划（概念块/中英扩展/缩写全称/各库检索式）、五源在线检索、24 小时查询缓存；支持 Semantic Scholar/CORE/任意 JSON API 自定义来源（账号/token/字段映射/测试连接/密钥隔离）；结果按“直接相关 / 方法参考 / 背景脉络”分层，并标注来源类型与题录可信度；多源并发聚合支持慢源冷却
- **混合检索**：BM25 候选集上加入术语/章节扩展的本地词法重排，配置 embedding 后可融合向量通道；问答显示检索模式，并对每条引用做原文 quote 核验
- **查阅**：TL;DR、问题/方法、章节节选、关键指标、图表/数值抽取、审稿人问题与页码级证据链；五栏精读笔记导出
- **翻译**：摘要/章节/整篇、中英对照、311 条内置术语 + 在线/本地扩展术语包、公式/引用/数字保护、缓存与双语 Markdown 导出
- **引用**：OpenCitations 参考/被引网络、Crossref 题录补全；研究库引用体检（缺项/重复/DOI 核验）
- **对比**：2–10 篇论文自动抽取字段，生成对比表、共识、分歧与可比性提醒
- **提炼**：作者声称 / 实验证据 / 模型推断三栏分离，附审稿人问题
- **转化**：复现计划、代码骨架、组会 Slides、课程案例与 Quiz
- **问答**：问题拆解、章节意图、支持度矩阵、可核对数值，答案附章节/页码
- **选题**：方法簇与年份版图、证据缺口、候选问题、四维可行性、论证卡、三阶段阅读路径、最小实验计划与导师沟通页
- **写作**：相关工作 / 提纲 / 摘要骨架，附引用键与参考文献；逐句主张—证据核查 + 结构论证体检
- **研究库**：收藏、状态、标签、笔记、引用体检，以及 Markdown/JSON/BibTeX 导出与 JSON 导入
- **来源与词库**：自定义论文 API、在线/本地术语包；检索留痕可导出 Markdown/CSV
- **空白**：研究空白雷达，附新颖性、可行性与最小验证实验

## 快速启动

完整源码在 `paperpilot/` 目录。

```bash
cd paperpilot
pip install -r requirements.txt
python run.py
```

或：

```bash
cd paperpilot
docker compose up --build
```

默认地址：`http://127.0.0.1:8765`。

## 运行模式

| 模式 | 触发条件 | 能力 |
|---|---|---|
| 离线规则模式 | 未配置 LLM key（默认） | 内置 5 篇真实 arXiv 元数据 + 2 篇全文解析；全部工作区可用；项目 Copilot 用意图路由 + 词法检索 + 模板回答；自适应 Agent 走规则 Planner/Critic 与离线简报；上传 PDF 使用规则抽取；问答为抽取式；无密钥翻译走公共接口 |
| 在线增强模式 | 配置任意 OpenAI-compatible endpoint | Copilot 在项目资产上生成带引用回答并通过接地校验（不通过自动回退）；语义核查可模型复核；增强上传 PDF 抽取、整篇翻译、证据问答综合与研究简报润色；可选 embedding 重排 |

自 6.2.0 起，在线增强模式可以**不碰环境变量**直接开启：顶栏「模型设置」选择 OpenAI、DeepSeek、月之暗面 Kimi、阿里通义千问、智谱 GLM 或任意 OpenAI 兼容网关，填入自己的 API Key 与模型名，先「测试连接」再「保存并启用」，当前实例立即切换；分用途模型可以为五类任务分别指定快/慢模型。生效优先级：界面设置 > 环境变量 > 内置默认。

配置模板见 `paperpilot/.env.example`。发布包不包含任何 API key；界面保存的密钥只写入当前实例的 `data/llm_settings.secrets.json`（仓库、交付包、线上镜像均不含）。

## 关键设计

1. **证据优先**：结构化字段尽量附 `section + page + quote`；找不到写“未提及”。
2. **三栏分离**：作者声称 / 实验证据 / 模型推断不混写。
3. **抽取层级可见**：全文节选、摘要级、规则抽取在 UI 中明确标注。
4. **可比性守卫**：不同工艺、验证方式、数据集、测试条件的数字不直接排序。
5. **问答可核查**：问题拆解 + 章节/字段意图 + 支持度矩阵；答案附章节/页码与可核对数值。
6. **选题从缺口来**：候选问题来自证据缺口与论文局限，并附最小实验与评分。
7. **写作先结构后核查**：草稿保留引用键；逐句核查标出证据不足与未出现的数值。
8. **研究可积累**：收藏、状态、标签、笔记持久化，可用 JSON 备份迁移、BibTeX 导出。
9. **可执行但诚实**：复现计划与代码骨架是学习脚手架，不承诺自动复现。
10. **翻译可核对**：公式、引用与 URL 先保护再翻译，数字自动比对；无密钥时标注公共接口额度，配置模型后可完整翻译。
11. **引用可追踪**：OpenCitations 参考/被引关系 + Crossref 题录，只展示可回链的 DOI 记录。
12. **助手先接地再回答**：Copilot 的每条事实性结论必须能回到项目资产；引用越界或没有引用时回退离线答案，建议动作不交给模型生成。
13. **离线可演示**：没有 API key 也能走完检索、阅读、翻译预览、问答、选题、写作、自适应研究任务与核查。
14. **自适应而非固定流水线**：Planner 按证据覆盖、引用支持、饱和度和开放问题决定下一步；核查不足会追问或扩展检索，预算耗尽会收束。
15. **任务可恢复**：任务按动作持久化；检索/选题检查点可人工确认与改选；重启后标记中断并可恢复，报告可单独下载。
16. **引用先核验**：每条引用 quote 回到对应证据块做原文匹配；核对失败标记为“待核对”，不把模型输出当作新证据。
17. **边界可见**：证据账本、开放问题、人工决策和预算都写入简报与界面，未解决问题不会被隐藏。
18. **模型自配、密钥自守**：谁调用模型就用谁的 key；密钥与配置分文件落在当前实例，接口只回掩码，公共实例可设为只驻留内存；配置的接口地址仍受自定义来源同一套 SSRF 校验约束。

## 已知局限

- 离线模式的结构化字段为人工校订的演示语料，不等于对任意论文的自动抽取。
- 上传 PDF 的作者/章节/图表/数值为规则抽取，可能受版式影响；配置 LLM 可增强。
- 证据问答的候选召回仍是词法检索（BM25 + 章节/字段意图）；混合检索只在 BM25 候选集上重排，不引入候选集之外的新证据；embedding 默认关闭，需要模型 key 与 `PAPERPILOT_EMBEDDINGS=1`。
- 自适应 Planner/Critic 默认是规则策略，不是专家级研究判断；它能暴露开放问题与预算边界，但选题价值仍需人工确认。
- 研究库与任务状态是单实例 JSON 文件，未实现账号体系与实时同步；任务 worker 为单进程单线程，不适合多用户并发或分布式执行。
- 项目、项目记忆与草稿同样是实例本地 JSON，实例替换后不保留；SSE 快照流由当前进程推送，反向代理可能缓冲事件流，前端会在连接异常时降级为轮询。
- 离线 `write` 动作产出的是绑定证据的待改写段落，仍需人工重写；草稿核查只检查证据锚点、引用与数值一致性，不提供 DOCX/PDF 排版，也不判定事实真伪。
- 检索分层、题录可信度、选题可行性与写作体检均为规则/元数据启发式，只用于筛选与讨论，不是最终裁决。
- 多源聚合设置 8 秒响应上限，超时来源会短暂冷却；引用体检的 DOI 核验需要联网，且只比较题名相似度。
- 自定义来源的字段映射、限额与返回结构由第三方 API 决定；Semantic Scholar 匿名请求可能 429，CORE 需要 token。
- 自定义来源 token/password 与术语包保存在当前实例本地，未做多用户隔离；在线术语包的许可与准确性由原项目决定。
- 界面配置的模型与密钥同样只属于当前实例：本地默认写入 `data/llm_settings.secrets.json`（不进仓库与交付包），公共实例设为内存模式后重启失效。多人共用一个实例时不要粘贴生产密钥。
- 真实模型只实测了 ModelScope 推理 API 的 `ZhipuAI/GLM-5.2` 一个供应商；其余厂商的鉴权细节、模型可用性与计费行为需使用者自行验证。
- 真实模型回答质量**没有人工评分**：金标集仍是构造集，`live_agent_check.py` 的通过率只说明链路可用，不是质量结论。
- 分用途路由只负责把模型名带到请求里，不校验该模型是否存在；填错的模型会在调用时以 4xx 返回，可先用「测试连接」发现。
- 界面配置只影响当前进程；多 worker 部署需要在每个进程分别配置（本项目按单进程设计）。
- 选题问题与写作草稿由规则模板生成，必须人工改写与核对；主张核查与论证体检不是事实真伪判定。
- 当前检索源以 arXiv / Crossref / Europe PMC / DOAJ / HAL 与用户配置 API 为主，IEEE/ACM 全文需开放获取或用户上传。
- 评测集规模较小，尚未做多评审一致性。
- 无密钥翻译依赖第三方公共接口，受每日额度与网络影响；整篇稳定翻译需要配置 OpenAI-compatible 模型。
- 引用网络只支持 DOI 记录；OpenCitations/Crossref 的覆盖范围、API 速率与高被引返回量会影响结果。
- Europe PMC/DOAJ/HAL 是外部来源，元数据与摘要以其 API 返回为准。
- 公共翻译会将所选章节原文发送给第三方服务；未公开论文请避免使用公共翻译。
- 术语表是阅读辅助，领域新译名仍需结合上下文确认。
