# 金标集标注指南

本指南用于把 `data/eval/golden/` 从“机器构造探针”升级为“人工标注金标集”。目标是
**4 个主题 × 每主题 6 篇论文、合计 ≥200 条已标注 claim–evidence 对，两人独立标注**。

> 机器构造的 `seed-constructed.json` / `seed-adversarial.json` 只用于回归规则，
> 它们的 1.000 指标表示“判定器与探针构造方式一致”，**不能当作人工标注质量**写进发布说明。

## 1. 主题与规模

| 主题 slug | 领域 | 论文数 | 标注条数下限 |
|---|---|---:|---:|
| `llm-inference-quantization` | LLM 推理与量化 | 6 | 50 |
| `rag-pipelines` | RAG 流水线 | 6 | 50 |
| `cim-adc` | 存内计算与 ADC | 6 | 50 |
| `recommender-systems` | 推荐系统 | 6 | 50 |

每篇论文抽取 8–12 条“带结论或数字的句子”，同一篇不要重复同一句。

## 2. 一条标注由什么组成

```json
{
  "id": "g-rag-pipelines-001",
  "paper_id": "2609.xxxxx",
  "claim": "检索增强把回答准确率提升到 78.4%。",
  "evidence_quote": "Retrieval augmentation raises answer accuracy to 78.4% on our benchmark.",
  "locator": "Abstract",
  "label": "supported",
  "annotator": "alice",
  "note": ""
}
```

- `claim`：待判定的主张，默认使用原文句子；如果要测“过度声称”，可以在句尾追加一个原文没有的从句。
- `evidence_quote`：**必须是论文原文的连续子串**。`golden_workbench.py check` 会验证；
  不允许改写、翻译、拼接两段不连续的文字。
- `label`：见下一节，只允许 `supported` / `partial` / `unsupported`。
- `locator`：`Abstract`、`Full text`，或 `Results · p.5` 这类可回查的位置。
- `note`：为什么这样标，尤其是 `partial` 与 `unsupported` 的边界。

## 3. 标签定义

| 标签 | 判定标准 |
|---|---|
| `supported` | 证据直接覆盖主张的核心结论与全部数值；允许同义改写，不允许新增结论。 |
| `partial` | 证据覆盖主张的一部分：缺少某个数值、主张明显长于证据、或只支持多个结论中的一个。 |
| `unsupported` | 证据没有覆盖主张：主题不同、方法/系统不同、数值全部属于另一组数据、或方向相反。 |

边界规则（与 `grounding.classify_claim` 对齐）：

1. **数值优先**：主张里的数值大多不在证据中，且整体词汇重合不高 → `unsupported`；
   只有一个数值缺失、其余逐字一致 → `partial`。
2. **方向冲突**：证据说“提高”，主张说“降低” → `unsupported`，并在 `note` 写出两句的方向词。
3. **否定冲突**：一方有否定词、另一方没有 → 至少 `partial`，`note` 说明。
4. **过度声称**：逐字句后追加原文没有的结论 → `partial`，不要标 `supported`。
5. **跨论文**：主张来自 B 论文、证据来自 A 论文 → `unsupported`，即使两篇同领域。
6. 拿不准时标 `partial` 并在 `note` 写清理由；不要为了“看起来一致”改成 `supported`。

## 4. 流程

### 4.1 准备候选

```bash
# 4 主题 × 6 篇真实摘要（Crossref + Europe PMC，已随仓库提交）
python scripts/golden_workbench.py build --corpus-dir data/eval/golden/corpus

# 若要从零抓取语料（需联网）
python scripts/fetch_golden_corpus.py

# 也可以用自己的论文清单（JSON 数组，字段：id/title/abstract/full_text）
python scripts/golden_workbench.py build --papers my-papers.json
```

输出在 `data/eval/golden/candidates/<topic>.json`，所有 `label` 为空。
`stats` 会显示每个主题的论文数、候选条数与缺口：

```bash
python scripts/golden_workbench.py stats
```

### 4.2 两人独立标注

把候选文件复制两份，分别填写 `label`、`annotator`、`note`。两人不要互看结果。
标注完成后各自校验：

```bash
python scripts/golden_workbench.py check alice/rag-pipelines.json --strict
```

`--strict` 会检查：引句是否原文子串、label 是否合法、每主题 ≥6 篇 / ≥50 条已标注。

### 4.3 合并与分歧裁决

```bash
python scripts/golden_workbench.py merge alice/rag-pipelines.json bob/rag-pipelines.json \
  --annotator-a alice --annotator-b bob \
  --out data/eval/golden/rag-pipelines.json
```

- 标签一致的条目直接采用。
- 不一致的条目 `label` 留空、`disagreement: true`，并写入 `disagreements` 列表。
- 合并文件状态为 `needs-adjudication` 时，`eval_content` 会跳过它。
- 第三人只裁决 `disagreements`，裁决后把 `status` 改为 `labeled`、清空未裁决项。

### 4.4 进入评测

```bash
python scripts/eval_content.py            # 只读 status=labeled 的集合
python scripts/eval_content.py --strict   # 阈值门禁
```

`eval_content` 会跳过 `human-required` / `unlabeled` / `needs-adjudication` 的集合，
不会把“没有标注”算成 0 分。

## 6. 禁止事项

- 不得用模型生成 `label` 后冒充人工标注。
- 不得修改 `evidence_quote` 让它“更像”主张。
- 不得删除分歧条目来抬高一致率。
- 不得把构造探针的指标写进 README/CHANGELOG 当作质量结论。
