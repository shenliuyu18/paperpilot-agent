# PaperPilot v6.3 设计规格：跨部件一致性自查

- 日期：2026-10-23
- 版本：6.3.0
- 状态：已实施
- 前置版本：v6.2.2

## 1. 背景

v6.2 的功能都在单点测试里通过，但“部件之间对不对得上”没有系统检查：证据说自己是原文引句，简报引用说能回查，草稿和稿件各有一个引用样式选择器，投稿包的标题来自稿件而不是项目。这类错误不会被单元测试抓到，因为每个部件单独看都正常。

本版以“自查找错”为目标：先写一套跨部件审计，再用它驱动修复。

## 2. 审计设计（`scripts/audit_consistency.py`）

一次离线演示链路：搜索 → Agent auto 运行 → 草稿（含证据/引用/主张）→ 稿件 → 投稿包（普通 + 双盲）→ 审稿（报告/映射/回复）→ 样式切换。共 42 项断言，分五组：

| 组 | 检查的关系 |
|---|---|
| E 检索 | 请求来源 vs 响应来源、题录字段完整、分层/年份、`/api/read` 返回的论文与请求一致 |
| A Agent | 动作标题与工具一致；精读输入/产物/标题同一篇；对比论文集合与行列；候选问题引用原文；追问题目与引用原文；证据回原文；简报图例/参考文献编号/计数 |
| B 草稿 | 证据与引用键存在；文内编号按首次出现；参考文献条目指向被引论文且无机械错位；核查问题指向真实段落；DOCX 正文一致；切 APA 后预览与导出同步变化 |
| C 稿件/投稿 | 稿件回读；标题页/投稿信用稿件标题而非项目标题；检查档案与请求一致、目标段落存在；投稿包 DOCX 与草稿一致、正文标题是稿件标题；亮点来自支持主张且章节一致；清单计数与检查接口一致；双盲去作者/单位/致谢 |
| D 审稿 | 统计与草稿主张一致；推荐等级与覆盖率合法；意见映射到真实段落；回复模板逐条包含原意见 |

审计只读公开 API 与产物文件，不写业务数据；失败项直接打印证据。

## 3. 修复项

1. **证据逐字**：内置语料 22 条证据里 10 条是改写/拼接。按原文句子重写（保留 label/section/page），并加审计项“引句必须是论文正文子串”。
2. **简报引用**：`_offline_report` 增加 `> 引用标记：[P1] = 标题` 图例，参考文献逐条加 `[P1]`；`_with_legend()` 对模型输出**丢弃模型写的图例并按运行论文顺序重建**（图例是引用解析的唯一依据，不能交给模型）。
3. **样式同步**：`manuscript.update_citation_style()` 与 `draft_service.update_citation_style()` 互为镜像，由 API 端点调用；镜像**不增加草稿 revision**（避免 409 打断另一端编辑）。稿件保存后前端派发 `paperpilot:draft-changed` 让草稿面板重载。
4. **预览渲染**：去掉抽屉额外渲染的编号 chip（条目文本已含编号），APA 不再显示编号。
5. **预览时序**：先读元数据，再按 `meta.citation_style` 请求预览/预检。
6. **GB/T 7714**：`_stop()` 保证 `et al.` 只跟一个句号。
