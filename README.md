# PaperPilot · 论文领航员

> 给第一次做文献调研的本科生与研究生：把「一个研究方向」变成一批**可核查、可复用、可继续推进**的研究资产，最后交出一份能交的稿子。
> 全程离线可跑，不填任何 API Key 也能走完检索 → 精读 → 对比 → 选题 → 初稿 → 核查 → 导出。

## 三分钟看懂

打开首页，右上角有 **「一键跑完一次完整研究」**：它用内置演示语料新建一个项目，跑完检索 → 精读 → 对比 → 选题 → 写作 → 核查 → 简报，然后自动打开该项目。离线约 1.5 秒，模型预算固定为 0，不消耗任何额度。

跑完你会看到三样东西：

| 产出 | 在哪里看 | 为什么重要 |
|---|---|---|
| 研究简报 | 项目 → 研究简报 / 下载 Markdown | 每个结论都带 `[Pn]` 图例与参考文献编号 |
| 证据账本 | 项目 → 证据 | 每条证据有论文、章节、页码与**逐字原文引句** |
| 带证据锚点的草稿 | 项目 → 草稿 | 每个块绑定证据 ID，可回原文页高亮核对 |

## 它解决什么问题

做一次文献调研的真实困境不是「没有文献」：

1. **关键词构造不出来** —— 中文方向词翻不出领域里的英文检索式，也不知道该查哪些库。
2. **读完记不住、笔记散落** —— 五篇论文的指标、方法、局限各在一处，横向比较全靠脑补。
3. **不知道「这句话有没有依据」** —— 写出来的论断和读过的原文对不上，引用了却查不回页码。

PaperPilot 把这三件事串成一条可复现的链路，并且**在每一个环节留下可回查的证据**。

## 三条硬约束

改代码时不要破坏这三条；它们是这个项目的产品定义，而不是实现细节。

1. **证据优先**：每个结论都能回到具体论文的章节/页码与原文引句；没有证据就明说没有；数值缺失时核查总评强制降级；不编造来源。
2. **关键判断留在人手里**：分层、可信度、可行性只是筛选提示；核查、矛盾检测、三档判定只标记并给理由，不代写正文、不做事实真伪裁决；所有建议动作必须用户确认。
3. **离线可演示**：默认规则模式无需密钥；模型只是增强，不是前提。

## 五个可验证的亮点

每一条都能用命令或界面动作复现，不是宣传语。

| 亮点 | 怎么验证 |
|---|---|
| **证据可回查** | 证据引句与本地 PDF 文本层逐字比对（一致性审计 A7 断言 22/22 是原文子串）；`GET /api/paper/{id}/locate?page=&quote=` 返回归一化高亮坐标；扫描件没有文本层时明确返回「未定位」，不伪造坐标 |
| **三档支持判定** | `POST /api/projects/{id}/draft/audit` 给出 supported / partial / unsupported / insufficient 与理由；句子里出现证据中没有的数值时总评强制降级（`scripts/evaluate.py` 41/41） |
| **从初稿到投稿包** | 草稿 → 稿件元数据（ORCID 校验位、通讯作者、贡献、数据可用性）→ 5 种引用样式 → DOCX/PDF → 10 文件投稿包（含双盲）→ 可校验的研究档案 |
| **模型调用可审计** | 所有模型出口统一走 `llm_gateway`（一致性审计 F1）；`/api/llm/audit` 记录用途、模型、时延、降级原因；运行的 `max_llm_calls` 与「成功且未缓存」的审计条数逐条相等 |
| **离线不是降级版** | 不配置密钥时，检索、精读、对比、选题、写作、核查、导出、档案全部可用；配置后只是把规则结果换成模型结果，失败仍回退并标记 `llm_degraded` |

## 三十秒跑起来

```bash
python -m venv .venv
.venv/bin/pip install -r paperpilot/requirements.txt
.venv/bin/pip install httpx            # 测试依赖，不在 requirements 里
cd paperpilot
../.venv/bin/python run.py             # http://127.0.0.1:8765
```

Windows 上把 `.venv/bin/` 换成 `.venv\Scripts\`。PDF 导出需要本机 XeLaTeX（可选；缺工具链时接口返回 503 而不是崩溃）。

想用模型：顶栏「模型设置」→ 选供应商 → 填接口地址、模型名与 API Key → 先「测试连接」→「保存并启用」，当前实例立刻切到在线增强，无需重启。也可以只配环境变量：

```bash
export PAPERPILOT_LLM_API_KEY=...
export PAPERPILOT_LLM_BASE_URL=https://api.deepseek.com/v1
export PAPERPILOT_LLM_MODEL=deepseek-chat
```

| Copilot 专项 | 13/13 | `python scripts/eval_assistant.py` |

一致性审计不是快照测试：它在一个演示项目里真的走完「检索 → Agent 运行 → 草稿 → 稿件 → 投稿包 → 审稿 → 换样式」，逐项核对引用编号、证据引句、样式同步与能力位。其中 5 条是结构不变量：F1（模型调用只能在网关里）、I1（外部 id 拼路径必须走共享净化器）、G1（打印脚本必须先声明控制台安全输出）、H1（机器可读 JSON 必须显式 UTF-8）、J1（ModelScope 推送前清包外文件、推送后校验远端树）。

## 边界（明确不做什么）

- **人工金标集尚未签字**：4 主题 × 6 篇真实摘要语料与 225 条未标注候选已就绪，但 `label` 必须由人填写。构造集的 1.000 只说明「判定器与构造成分一致」，不是真实论文上的质量结论。
- **模型回答质量没有人工评分**：真实端点跑通过完整链路（预算账实一致、引用可回查），但只有少数供应商/模型，回答好坏没有人打分。
- **不做事实真伪裁决**：核查衡量的是「措辞重合 + 数值是否出现」，不是判断对错。
- **单实例**：项目、上传文件与研究库是本地 JSON，没有多租户隔离；不要把不可信用户接到同一实例。
- **embedding 重排不进审计**：它只重排 BM25 候选集，不会引入候选集之外的新证据；默认关闭。
- **投稿档案是参考要求**，不是期刊官方模板；审稿视角是规则自查，不是同行评审。

## 术语

- **运行（run）**：一次自适应研究任务，Agent 自主决定检索/精读/追问/对比/选题/写作/核查/收束的顺序。
- **项目（project）**：顶层实体，下挂多轮运行与跨轮记忆。
- **草稿（draft）**：项目级结构化 Markdown（章节 + 段落块），段落可绑定证据 ID 与引用键。
- **主张（claim）**：段落内的一条可核查断言，带三档支持判定与理由。
- **稿件（manuscript）**：项目级元数据 + 引用样式，决定导出时的文内标记与参考文献表。
- **订阅（subscription）**：保存的检索式与游标，用于增量发现新论文并做差异分类。
- **研究档案（dossier）**：把项目、运行、证据、草稿与历史装进一个带逐文件哈希的 ZIP。
